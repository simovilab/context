## Directives (composed)

### code.review-and-commits

Changes must land via reviewed pull requests. Use Conventional Commits (feat, fix, docs, chore, refactor, test, perf, ci) for all commit messages.


_from: project_

### data.fair-mdip

Published data must be Findable, Accessible, Interoperable, and Reusable (FAIR), and must align with the Mobility Data Interoperability Principles (MDIP).


_from: project_

### data.gtfs-standard

GTFS is the canonical exchange format for this system: GTFS Schedule for static data and GTFS Realtime Alerts for operational alerts.


_from: project_

### data.no-pii

Never collect, store, or publish personally identifiable information (PII). No PII is required for this system, and this is a hard commitment, not a target.


_from: project_

### data.open-license

Published GTFS data must use an open, permissive license (recommended: Creative Commons Attribution 3.0 / CC BY 3.0). Published data is open and public domain, with no access or use restrictions.


_from: project_

### security.audit-logging

Handling of public-transport data must produce activity logs sufficient for traceability, audit, and anomaly detection (CS6).


_from: project_

### security.database-hardening

Databases must sit behind authentication with strong credential and password policies, and must have periodic backup policies to prevent data loss (CS3).


_from: project_

### security.no-sensitive-in-source

Source code must never contain personal, institutional, or business-sensitive data; never commit secrets, credentials, or internal URLs (CS2).
