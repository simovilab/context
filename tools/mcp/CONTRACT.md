# InfoTP Context MCP Server — Contract (P4, FROZEN)

The **third face** of the Context Studio: it serves the project's context to
**agents** over the Model Context Protocol (MCP). The other two faces are the
authoring UI (P2) and the git store (canonical). This face is **read-only**: it
never writes the store, never commits, never mutates anything.

It serves the two halves of the core model to a working agent:

- **Directive context** — the composed, specificity-resolved, token-budgeted
  rule block for a node (inlined). Served from the committed `.composed/<id>.json`
  (D4), with an opt-in `live` recompute.
- **Reference context** — branch-scoped retrieval over the node's accumulated
  reference corpus (fetched on demand, D10). Served by shelling to `infotp_rag`.

This document is the single source of truth for the MCP seam. The implementer
follows it exactly; it does not get to redesign the surface.

---

## 0. Non-negotiables (inherited)

- **Read-only.** No write/commit/PR path exists in this package. The only side
  effects permitted are: reading files under `<repo>/.composed/`, and spawning
  the two pinned Python CLIs (`infotp_composer`, `infotp_rag`) with validated
  argument arrays.
- **Self-hosted, offline.** stdio transport only — no HTTP server, no ports, no
  outbound network. The Python CLIs are offline; the default RAG embedder falls
  back to the offline `hashing` backend if `semantic` is unavailable.
- **No PII, no secrets, no internal URLs** surfaced. Corpus `source` fields are
  provenance text only (already enforced upstream in P3). This server adds no
  new data; it only relays what the store already commits.
- **Sonnet subagents implement; Opus owns this contract.** Do not edit this file
  during implementation; if something here is impossible, stop and report.

## 2. The node catalog (D4 boundary)

The server derives its **node catalog** by reading `<repo>/.composed/*.json` —
the committed composed artifacts. This is the language-neutral contract boundary
D4 intends: no `node.yaml` parsing in TS, no Python needed to list or validate.

- `src/catalog.ts` — reads every `.composed/*.json`, returns an immutable map
  `id → CatalogEntry`. Loaded once at startup; the process is short-lived per
  agent session, so no watch/reload is required (document this).
- `CatalogEntry` fields (all from the composed JSON): `id`, `name`, `component`
  (`string | null`), `kind` (`Kind[]`), `status`, `hito` (`string | null`),
  `due_month` (`number | null`), `depends_on` (`string[]`). Plus a **derived**
  `layer`: `project` → `"project"`; id matching `^C[1-7]$` → `"component"`;
  everything else (`C#P#`, `INF#`) → `"deliverable"`.
- The catalog is also the **id-validation allow-list** (§5).
- If `.composed/` is missing or empty, fail fast at startup with a clear message
  ("no composed artifacts found — run `infotp_composer compose --all` first").

## 3. MCP tools (agent-invoked)

Register with `server.registerTool(name, { title, description, inputSchema,
outputSchema? }, handler)`. `inputSchema` is a **plain object of zod fields**
(not a wrapped `z.object`). Every handler returns
`{ content: [{ type: "text", text }], structuredContent }` on success and
`{ content: [{ type: "text", text }], isError: true }` on failure. `text` is a
short human summary; `structuredContent` carries the machine payload below.

### 3.1 `list_nodes`
- **inputSchema**: `{ layer?: z.enum(["project","component","deliverable"]).optional(), component?: z.string().optional() }`
- Returns the catalog, optionally filtered by `layer` and/or `component`.
- `structuredContent`: `{ nodes: CatalogEntry[] }` (stable sort by id).
- No Python shell-out.

### 3.2 `get_directives` — the directive face
- **inputSchema**: `{ node_id: z.string(), live: z.boolean().optional() }`
- Default (`live` falsy): read `<repo>/.composed/<node_id>.json` and return it.
- `live: true`: recompute via
  `composer compose <node_id> --stdout --json --tokenizer <configured>`
  (uncommitted working-tree freshness).
- `structuredContent`: the `ComposedView` object (id, name, component, kind,
  status, owner, result, depends_on, hito, due_month, chain, `directives[]`
  each `{key,text,applies_to,lang,sources}`, `reference[]`, `token_estimate`).
- `text` summary: e.g. `C1P1 — 8 directives, ~412 tok (heuristic); chain: project → C1 → C1P1`.

### 3.3 `search_reference` — the reference face (confidentiality boundary)
- **inputSchema**: `{ node_id: z.string(), query: z.string(), k: z.number().int().optional(), embedder: z.enum(["hashing","semantic"]).optional() }`
- Shells `infotp_rag query <node_id> "<query>" -k <k> --embedder <e> --json`.
- **Branch-scoping is enforced inside `infotp_rag`** (parent_chain mask); this
  server never reimplements or relaxes it. An agent scoped to `C1P1` can only
  retrieve `project`/`C1`/`C1P1` corpus — never a sibling branch (`C2…`).
- `k`: default 5, clamp to `[1, 20]`. `query`: reject empty; cap at 2000 chars.
- `embedder`: default = configured `INFOTP_MCP_EMBEDDER` (`semantic`), with the
  per-request semantic→hashing fallback from `rag.ts`.
- `structuredContent`: `{ embedder: string, fallback: boolean, results:
  RetrievedChunk[] }` where `RetrievedChunk = {score,text,node_id,file,title,ordinal}`.
- `text` summary: e.g. `3 chunk(s) via hashing (fallback) for "…" scoped to C1P1`.

### 3.4 `get_budget` — the guardrail
- **inputSchema**: `{ tokenizer?: z.enum(["heuristic","tiktoken"]).optional() }`
- Shells `composer budget --json --tokenizer <t>` (default configured tokenizer).
- `structuredContent`: the `BudgetReport` (`{tokenBudget, components[], overflows[]}`).
- `text` summary: budget + any overflows.

## 4. MCP resources (browsable context)

For MCP clients that prefer readable resources over tool calls. Register with
`server.registerResource`.

### 4.1 `context://tree` (static)
- `description`: "The InfoTP context node catalog."
- Read → `{ contents: [{ uri, mimeType: "application/json", text: JSON.stringify({nodes}) }] }`
  (same payload as `list_nodes`).

### 4.2 `context://node/{id}/directives` (ResourceTemplate)
- Template: `new ResourceTemplate("context://node/{id}/directives", { list: undefined })`.
- `id` validated (§5); unknown → throw `ResourceNotFoundError(uri.href)`; malformed
  → `ProtocolError(ProtocolErrorCode.InvalidParams, …)`.
- Read → the committed **markdown** directive block `<repo>/.composed/<id>.md`
  as `{ contents: [{ uri, mimeType: "text/markdown", text }] }`.

## 5. Input validation (security boundary)

Applied **before** any file read or spawn:

- **`node_id`**: must match `^(project|C[1-7]|C[1-7]P[0-9]{1,2}|INF[1-3])$`
  **and** be a member of the catalog (§2). Fail either → `isError` (tool) /
  `ResourceNotFoundError` or `InvalidParams` (resource). Never spawn or read a
  path built from an unvalidated id.
- **`query`**: non-empty after trim; length ≤ 2000; passed only as a spawn
  **argument** (never interpolated into a shell string — spawn uses an arg array).
- **`k`**: integer, clamped to `[1, 20]`.
- **Error text is sanitized**: agent-facing messages carry a short reason only —
  never a stack trace, never an absolute filesystem path, never raw CLI stderr
  beyond a trimmed first line. (Log full detail to the server's stderr, which is
  the operator's channel, not the agent's.)

## 6. Configuration (env)

| Var | Default | Meaning |
|---|---|---|
| `INFOTP_REPO` / `STUDIO_REPO` / `--repo` | auto-discovered (walk up for `schemas/`+`project/`) | Repo root. `INFOTP_REPO` wins, then `STUDIO_REPO`. |
| `STUDIO_PYTHON` | repo `.venv`, else `python3` | Interpreter with `infotp_composer`+`infotp_rag` (reuse `resolvePythonBin`). |
| `INFOTP_MCP_EMBEDDER` | `semantic` | Default `search_reference` embedder; per-request fallback to `hashing`. |
| `INFOTP_MCP_TOKENIZER` | `heuristic` | Default tokenizer for `get_directives --live` and `get_budget` (heuristic matches the committed `.composed/` numbers). |

Startup logs (to **stderr**, so stdio JSON-RPC on stdout stays clean): server
name/version, resolved repo root, resolved Python, catalog node count, embedder,
tokenizer.

## 7. Entry point

`src/index.ts`:
1. Resolve repo root + load catalog (fail fast on error).
2. `new McpServer({ name: "infotp-context", version: "0.1.0" })`.
3. Register the four tools (§3) and two resources (§4).
4. `await server.connect(new StdioServerTransport())`.
5. All human logging goes to `console.error` (stderr) — **stdout is reserved for
   the JSON-RPC transport**; a stray `console.log` corrupts the protocol.

Keep files small and focused (per repo style): `catalog.ts`, `validate.ts`,
`config.ts`, `python.ts`, `repo.ts`, `composer.ts`, `rag.ts`, `tools.ts`
(registrations), `resources.ts` (registrations), `types.ts`, `index.ts`.

## 8. Tests (vitest)

- `catalog`: reads a small fixture `.composed/` dir → correct entries + derived layer.
- `validate`: accepts `project`/`C1`/`C1P1`/`INF1`; rejects `C9`, `c1p1`,
  `C1P1;rm`, `../x`, empty, and ids absent from the catalog.
- `tools`: each handler with a **mocked** spawn (no real Python) — assert it
  builds the correct arg array (esp. that `search_reference` forwards `node_id`
  unchanged → branch-scoping), clamps `k`, and shapes `structuredContent`.
- `resources`: `context://tree` payload; `context://node/{id}/directives` returns
  markdown for a known id and `ResourceNotFoundError` for an unknown one.
- One **integration** test (skip if no repo `.venv`): real `search_reference` on
  `C1P1` returns ≥1 result AND the same query scoped to a `C2*` node returns 0
  (branch isolation) — the P3 security property, re-asserted at the MCP layer.

## 9. Non-goals (P4)

- No write/commit/PR, no authoring — that's the Studio (P2).
- No HTTP/SSE transport, no auth, no multi-tenant — stdio, single local agent.
- No re-implementation of composition, chunking, embedding, or scoping — those
  live in Python behind the frozen D4/D10 contracts; this server only relays.
- No caching/watch/reload — short-lived process per agent session.
